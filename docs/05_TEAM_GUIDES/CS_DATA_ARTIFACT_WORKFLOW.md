# CS Data and Artifact Workflow Guide

This guide is for the CS side of the team.

## Rule of thumb

- Code goes to GitHub.
- Data/model/output goes to Google Drive.
- Notebooks are allowed, but notebooks must call repo code instead of hiding all logic inside cells.

## Before a training run

1. Choose a stream: `cv_yolo`, `rl_sumo`, or `public_finance`.
2. Create or confirm a dataset row in `00_Data_Model_Run_Registry`.
3. Create a local run folder with `scripts/artifacts/prepare_run_dir.py`.
4. Fill `run_config.json`.
5. Run locally, Colab, or Kaggle.

## After a training run

1. Save metrics, logs, model files, predictions, traces, and reports into the run folder.
2. Push the run folder to Drive Data Hub.
3. If the model is worth keeping, copy selected model files to `04_Model_Artifacts`.
4. Update the registry sheet.
5. If Economics needs to read it, export a short report to `05_Reports_For_Team`.

## YOLO now, without overclaiming

YOLO is treated as the future sensor layer:

```text
camera/video -> YOLO detects vehicles -> counts by type/time -> simulation/RL observation input
```

For now, we prepare dataset folders, notebook skeletons, and environment requirements. We do not
claim YOLO accuracy until a real labeled dataset and evaluation exist.

## RL data meaning

RL does not start from a fixed CSV dataset. Its training data is generated by interaction:

```text
observation -> action -> reward -> next observation
```

The durable assets are the environment spec, generated SUMO files, run config, rollout traces,
metrics, and checkpoints.
